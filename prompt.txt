Act as a Principal Software Architect, Distributed Systems Engineer,
SaaS Platform Architect, Database Architect, and Hardware Integration
Architect.

Design a production-grade, highly scalable, secure, observable,
multi-tenant Gym Management SaaS platform modeled after modern fitness
operating networks such as GymForce Pro.

The goal is NOT to design a generic CRUD application.

Design a system suitable for thousands of gym organizations, multiple
branches per organization, millions of members, high-volume biometric
access events, financial transactions, asynchronous notifications,
offline operation, third-party integrations, and future mobile clients.

Use concrete architecture, domain boundaries, database schemas,
API contracts, state machines, sequence diagrams, concurrency controls,
failure handling, infrastructure topology, and implementation examples.

Every major architectural decision must include:
- Why it exists
- Where it executes
- Data ownership
- Failure modes
- Scaling implications
- Security implications
- Operational implications

Clearly distinguish:
OBSERVED / INFERRED / RECOMMENDED architecture where assumptions about
the reference application are involved.

boundaries for future services.

6. TENANT-SCOPED MEMBER IDENTIFIERS
============================================================

Show the SQL implementation.

Example:

while maintaining an immutable global member UUID.
